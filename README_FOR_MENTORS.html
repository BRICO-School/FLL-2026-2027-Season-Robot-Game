実行モードの決まり

!
子どもに徹底させる、いちばん大事な決まり。
  • 開発中は selector.py を触らず、自分の run_*.py だけを F5 で回す。誰かが壊しても他人に波及しない。
  • 完成した run は大会直前に programs へ登録し、全プログラムを通しで確かめる。
  • selector.py の登録と並び替えはメンターか担当者 1 名が行う。同時に編集するとコンフリクトが頻発する。

しくみを順に追う

開くと、各部品が何をしていて、どこに気をつけるかが分かる。

1 · setup.py — 全 run の共通基盤 setup.py

initialize_robot() は hub・robot・左右のタイヤ・左右のリフトの 6 要素を返す。子どもの run はいつもこれを受け取る。

Robot クラスは呼び出しごとに速さ・加速度・timeout を指定でき、終わると既定値に戻す。

NullMotor はリフトが未接続でも落ちないためのダミー。タイヤは必須で、未接続なら例外になる。

2 · selector.py — 競技の入口 selector.py:53

programs に登録した run を左右ボタンで選び、フォースセンサーで走らせる。いま登録されているのは run_template だけ。

initialize_robot() は始めの 1 回だけ。ミッションごとは reset_robot() で距離と向きを 0 に戻し、待ち時間は無い。

dev フラグはいま False。True にすると、センサーの値を出すタスクが multitask で並走する。

3 · run_with_log.py — 記録つきの実行 run_with_log.py

画面の出力を docs/logs/ に保存し、走行後にファイル名のミッションの順に成否を 1 つずつ聞く。確認で Enter を押すと trials.csv に足す。

記録のたびに dashboard.html と dashboard_coach.html を作り直す。名前に coach が入る run の記録はチームの方に数えない。

verification/ などのスクリプトは .hub_stage/ に setup.py と写して送る。成否を数えない走行には --no-trial を付ける。

4 · ハードウェアのポート割付 README_FOR_MENTORS §3.4

フォースセンサーは 2026-09-19 に Port C から D に変わった。ハブ姿勢は top_side=Axis.Z, front_side=Axis.X。

5 · 手押しティーチング scripts/teach.py

ハブ側の teach_record.py が手で押したルートを記録し、PC 側の scripts/teach.py が straight・turn・curve と run_angle のコードを起こす。記録は docs/logs/teach_record/ に残る。

1 つの動きごとに手を止め、持ち上げない。タイヤが床で回らないと距離が分からない。

起こしたコードはそのまま使えないことが多い。run_coach_M03_teach.py と run_coach_M04.py も距離や速さを手で直している。

setup.py で決まっていること

全 run に効く判断と、その理由。右は決めた日。

  • 寸法は本番機で測って確定した09-17車輪径は 62.32mm。トレッドは 114.48mm。機体を作り直したら測り直す。
  • PID は Pybricks の既定値をそのまま使う09-17KI を足しても良くならなかった。昨年値は old で残してある。
  • DRIVE_SETTINGS で new と old を切りかえる09-18比較では直進と回転は new、正方形の終点は old が良く、割れた。
  • ハブ名で校正表 ROBOT_PROFILES を引く09-17ジャイロの目盛りはハブごとに違う。校正前の Hub3 は turn(90) で約 88.7° しか回らなかった。
  • Hub3 の heading_correction は 360.109-19 · 暫定止まってから回れば状態 B になる。365.8 のままだと B のとき回りすぎる。
  • 始めに止まったまま 2 秒待つ09-19始めてすぐ回ると状態 A になる。A では回転が約 1.4% ずれる。
  • 回転の打ち消しは既定で使わない09-17Pybricks は命令した角度の合計を目標の向きに保つ。打ち消すと逆にずれた。
  • correct=True も使わない09-17係数が再現しなかった。いまは校正表で合わせる。
  • turn と straight は整数に丸めるsetup.pyturn(42.5) のような小数の角度は効かない。

手押しの記録とコードの記法

teach.py が読むのは # teach: の行と P, で始まる行だけ。● 動き N の行は区切りの目安で、本当の区切りは teach.py が決め直す。

読み取りは 40ms ごと。行が出るのは、角度が変わったとき・向きが 0.5° 以上変わったとき・止まっていても 1 秒ごと。

# docs/logs/teach_record/20261002_205805.log から抜粋
# teach: wheel=62.32 axle=114.48 hub=Pybricks Hub3
# 列: P,ms,左タイヤ(度),右タイヤ(度),向き(0.1度),左アーム(度),右アーム(度)
P,0,0,0,0,0,0
P,482,-1,0,0,0,0
● 動き 2 : 進んだ 675 mm / 向き -39.3 ° / 左アーム 1 ° / 右アーム -1 °
P,19655,1432,1603,-437,1,-1   # 19.655 秒・左に 43.7° 向いている
# uv run python scripts/teach.py docs/logs/teach_record/20261002_205805.log
    await robot.curve(1365, 26)  # カーブ 半径 1365mm・右 26°（前進 619mm）
    await robot.curve(-49, 65)   # カーブ 半径 49mm・左 65°（前進 55mm）
    await robot.turn(-3)         # 向きを合わせる 左 3°
    await robot.straight(151)    # 前進 151mm

確認: このコードの終点は、手で押した終点から 26mm・向き -1.7° ずれ

P, 行の列

列単位中身
msミリ秒記録スタートからの時間
左タイヤ・右タイヤ度駆動モーターの角度。前に押すと増える
向き0.1 度ジャイロの向きを 10 倍した整数。時計回りの右が＋で、-437 は左に 43.7°
左アーム・右アーム度リフトのモーター角度

teach.py が出すコード

動き出るコード符号
直進await robot.straight(距離mm)＋前進・−後退
その場回転await robot.turn(角度)＋右・−左。直進やカーブの前に向きを合わせる回転が入ることがある
カーブawait robot.curve(半径mm, 角度)半径は＋右回り・−左回り。角度は＋前進・−後退
アームawait left_lift.run_angle(速さ, 角度)右は right_lift。角度の−は逆回し。速さは --arm-speed で、既定 500
数字はすべて整数で、速さは書かない。

支援で気をつけること

  • 子どもの run ファイルを勝手に整形しない。F5 の ruff はリポジトリ全体を整形するので、他人の未コミットの変更にも手が入る。構造を変えるときは本人と一緒に。
  • 走らせる前に、置いて手を離す。initialize_robot() は止まったまま 2 秒待つ。持ったままだと 10 秒で警告を出して進む。
  • コーチの確認走行は名前に coach を入れたファイルで。チームの成功率と見こみ点にコーチの走行が混ざらない。
  • 成否はミッションごとに、届かなかったら - を。前のミッションの失敗で後ろのミッションの成功率が下がらない。記録後のまちがいは scripts/trial_fix.py で直す。
  • setup.py の変更は全 run に効く。物理値や PID を変えたら直線・スクエア・カーブを測り直し、docs/ に残す。
  • selector.py は競技本番の生命線。dev フラグの取り違えや programs の順序ミスは本番事故に直結する。
  • docs/logs/ は git で管理している。手押しの記録からコードを起こしたら、もとの記録も一緒にコミットする。
  • 複数 PC では別ブランチで作業し、メンターがマージする。特に selector.py と setup.py を同時に編集させない。
  • launch.json の PYTHONUTF8 を消さない。Windows での文字化け対策になっている。
